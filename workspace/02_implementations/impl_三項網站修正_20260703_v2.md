## 技術決策日誌

| 決策項目 | 選擇 | 原因 |
|---------|------|------|
| 縮圖後是否覆寫原檔 vs 另存新檔 | 直接覆寫同檔名 | 4 張圖均已被 Git 追蹤，覆寫同檔名可保持 index.html 路徑不變，無需修改 HTML，commit 後 Git history 也更清晰（同一路徑的大小變化一目了然）。若另存新檔則需同步修改 index.html 4 處路徑，引入額外 diff，風險更高。 |
| 縮圖目標長邊尺寸 | 1200px | 顯示容器為 `md:grid-cols-3`（桌面每格約 300-400px），1200px 可涵蓋 3x Retina 顯示（400×3=1200），品質足夠且已大幅降低解碼量。Evaluator 建議範圍為 1000-1200px，選上限確保高 DPI 裝置畫質。 |
| WebP 輸出品質參數 | quality=85 | Pillow WebP quality=85 在肉眼品質與壓縮率之間達最佳平衡；低於 80 在食材近攝紋理圖上可能出現明顯 artifacts，高於 90 則檔案大小收益遞減。結果：最大 75.2KB（地瓜豆），視覺品質良好。 |
| 重採樣演算法 | LANCZOS | Pillow 提供最高品質的下採樣重採樣方法，適合從極高解析度縮至中等解析度的場景，能保留食材紋理細節。 |
| lazy loading 判斷標準 | 非首屏 section 內的所有 img | Hero（`<header class="h-screen">`）及 `<nav>`（固定頂部）屬首屏常駐可見元素，其餘所有 section（品牌故事、經典產品、精選甜品、嚴選食材、Footer）均在首屏下方，使用者需捲動才可見，一律加 lazy。 |

- **問題 #3（Medium，未處理）**：Evaluator 指出食材圖 `<img>` 未設 `width`/`height` 屬性，存在潛在 layout shift 風險。外層已有 `aspect-[3/4]` / `aspect-[4/5]` 可緩解 CLS，但若後續要進一步優化 CWV 指標，可補上此屬性。本輪未動此項，以避免超出退回修正範圍。
- **問題 #4（Low，未處理）**：`tailwindcss.exe` 未加入 `.gitignore`。建議後續確認並補上，避免大型二進位誤入 Git。
- **問題 #5（Low，未處理）**：Google Fonts 重複引入（`<head>` 第 18-20 行與第 25-27 行）。建議後續合併為單一請求並上移 `preconnect`，與本次修正範圍無關。
- **圖片視覺確認**：縮圖已確認像素尺寸與檔案大小，但縮圖後的畫質（尤其地瓜豆紋理較細膩）建議在瀏覽器實機確認，若有 artifacts 可調高 quality 至 90 重跑。
- **Git LFS**：原 4 張圖片若在 Git LFS 管理範圍，覆寫後需確認 `git lfs track` 規則仍正常生效，避免 LFS pointer 與實際檔案不一致。

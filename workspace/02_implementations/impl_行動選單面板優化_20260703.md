## 技術決策日誌

| 決策項目 | 選擇 | 原因 |
|---------|------|------|
| hover 色 `hover:text-[var(--accent-red)]` → `hover:text-brand-gold` | 採用（調整） | 計畫列為「建議採棕金」，與全站 `hover:text-brand-gold` 慣例一致；紅色 `#A62121` 在輕柔暖米白底面板上對比過強，棕金 `#A38B71` 更貼近「輕柔留白」調性 |
| 桌機原有兩段重複 `@media (min-width: 768px)` | 合併為一段 | 原 CSS 有兩段功能重疊的桌機 media query（第 302-308 行、第 310-326 行），後段覆蓋前段，合併後邏輯更清晰，減少維護混淆；`.active` 狀態與 `:not(.active)` 規則均保留 |
| 連結改為 block-level flex（新增 `.mobile-dropdown a`） | 採用 | 原連結為 inline 文字，觸控高度不足；以 `padding: 12px 24px` 搭配 `display:flex` 確保每項可點高度 >=44px，符合 WCAG 觸控標準 |
| `backdrop-filter` fallback | `background: #F9F8F6` 宣告在 `rgba(...)` 之前 | 不支援 backdrop-filter 的環境（舊 Android、部分 Firefox 版本）會使用第一條 `background: #F9F8F6`（不透明暖米白），文字仍清晰可讀；支援的環境則套用 `rgba(249,248,246,.85)` 半透明 |
| 桌機寬度由 200px 微調至 220px | 採用 | 加入 `padding: 16px 0` 後連結文字橫向需要更多呼吸空間；220px 在現有右側定位下不超出視窗，視覺比例更佳 |

## 已知限制或待確認事項

- `backdrop-filter: blur()` 在 Safari iOS 14 以下、Firefox 尚未設定 `layout.css.backdrop-filter.enabled` 的情境無效，已提供實色 fallback，視覺不會破損但無毛玻璃效果。
- 手機版動畫仍為 `translateX(100%)→translateX(0)`（從右側滑入），計畫方案 A 說明「可改為 translateY+scale 的下拉感」，本次維持原 translateX 動畫方向（避免改動 `.active` class 的展開邏輯），若客戶希望手機版也改為從上方滑入可於後續單獨評估。
- 連結點擊區高度 `12px padding + 18px font-size line-height` 約 44–48px，已達 WCAG 觸控標準，但實機觸控體驗建議以真實裝置驗收。

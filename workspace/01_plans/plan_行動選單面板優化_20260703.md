# 執行計畫：行動選單面板（mobileDropdown）視覺優化

**建立日期：** 2026-07-03
**版本：** v1.0
**狀態：** 已完成（2026-07-03 驗收通過，見 workspace/03_evaluations/eval_行動選單面板優化_20260703_v1.md）

---

## 需求摘要

將手機版導覽選單（`id="mobileDropdown"`）由目前的「右側滑入條狀下拉」優化為視覺更精緻的「面板（panel）」形式，並使其配色、圓角、陰影、動畫節奏與全站「輕柔、留白、詩意」的東方生活美學風格一致。此為使用者當下直接提出的視覺優化需求，屬既有元件的樣式精修，非新增品牌方向決策；桌機版下拉選單既有行為與整組開合狀態管理（含 aria 屬性）必須維持不受影響。

## 現況分析（Read 後的事實記錄，供 Generator 對照）

### HTML 結構（index.html 第 376–397 行）
- `<nav id="navbar">` 內含品牌 Logo、`<button id="menuToggle" class="mobile-menu-btn">`（漢堡按鈕，已含 `aria-label` / `aria-expanded="false"` / `aria-controls="mobileDropdown"`）。
- `<div id="mobileDropdown" class="mobile-dropdown">` 內含 4 個錨點連結：
  - 品牌故事 `#brand-story`、精選甜品 `#portfolio`、嚴選食材 `#ingredients`、門店資訊 `#contact`
  - 每個 `<a>` 帶 `class="text-black hover:text-[var(--accent-red)] transition-colors"`。
- 選單容器與漢堡按鈕的定位錨點為 `<div class="md:relative">`（第 379 行）與 nav（`position:fixed`）。

### CSS 現況（index.html `<style>` 第 273–345 行）
- `.mobile-dropdown` 基礎：`position:absolute; right:0; top:100%; width:256px; background:#FFDAC8; border:1px solid #E5E5E5; box-shadow:-2px 0 10px rgba(0,0,0,.1);` 直向 flex 置中、`gap:24px`、`font-size:18px`。
- 初始隱藏：`transform:translateX(100%); opacity:0; transition:transform .3s ease, opacity .3s ease;`
- 手機版（`max-width:767px`）：維持 `width:256px`，靠 `translateX(100%)→translateX(0)` 從**右側滑入**。
- 桌機版（`min-width:768px`）：改 `width:200px`，`transform:translateY(10px)→translateY(0)`，加 `visibility:hidden→visible`，`box-shadow:0 4px 15px rgba(0,0,0,.1)`——即**由上而下淡入下拉**。
- `.active` 為統一的展開 class（手機 `translateX(0)`；桌機 `translateY(0)+visibility:visible`）。

### JS 邏輯現況（index.html 第 845–882 行）
- `menuToggle` click：`toggle('active')`，同步 `mobileDropdown.active`、`aria-expanded`、`aria-label`，並清除 `hideTimeout`。
- `mobileDropdown` `mouseleave`：延遲 500ms 關閉（桌機 hover 行為）。
- `document` click：點擊選單與按鈕以外區域關閉，並復位 aria。
- 錨點 `a[href^="#"]` click：平滑捲動後關閉選單（第 839–842 行）。

### 現況判定
- 目前**不是**卡片面板，也**不是**毛玻璃或全螢幕遮罩；而是「右側滑入的窄條狀下拉（手機）＋上方淡入下拉（桌機）」，兩種樣式共用同一 HTML/JS，僅靠 media query 分流。
- 背景色 `#FFDAC8`（粉橘）與 `border-color #E5E5E5` 為**硬編碼**，未使用專案色票（`brand-bg #F9F8F6`、`brand-gold #A38B71`、`brand-accent #B0B7B0`），與全站暖米白／棕金／鼠尾草綠調性略有落差——此為本次「風格一致性」優化的核心切入點。

### 可複用的全站「輕柔」視覺語彙（優化時應套用，而非另創一套）
- 色票變數：`--bg-color #F9F7F2`、`--accent-gold #FFB380`、`--accent-red #A62121`；Tailwind `brand-bg/text/accent/gold`。
- 漸層語彙：`.img-gradient-border` 與 `.fixed-bg` 皆用 `linear-gradient(135deg, #FFF9F2 0%, #FFB380 100%)`——面板背景或邊框可沿用此漸層以呼應全站。
- 圓角慣例：圖片區塊 `rounded-[10%]`、`.img-gradient-border` 用 `border-radius:16px`（外）/`8px`（內）。
- 陰影慣例：`shadow-sm`、`0 4px 15px rgba(0,0,0,.1)`（現有桌機下拉）。
- 動畫節奏：CSS transition 慣用 `.3s ease`（選單）、`duration-500`/`duration-700`（navbar、圖片 hover）；AOS `duration:1000, easing:'ease-out-quad', once:true`。
- 毛玻璃前例：navbar 捲動後採 `bg-white/95 backdrop-blur-sm`——毛玻璃在本站已有使用先例，套用於面板不會突兀。
- 襯線體：標題用 `font-serif`（Playfair Display / Noto Serif TC）。
- 字色 hover：全站慣用 `hover:text-brand-gold`；現行選單卻用 `hover:text-[var(--accent-red)]`（紅），可評估統一為棕金以更貼近輕柔調性。

## 面板呈現方案比較

> 三案皆為純 CSS/Tailwind 可達成，**無需新增任何圖片素材**（波紋背景 `wave.svg` 若需點綴亦為現成資源）。

### 方案 A：上方滑入的卡片式下拉面板 ＋ 毛玻璃 ＋ 圓角 ＋ 輕柔陰影【建議】
- **描述：** 保留現有「navbar 右側、top:100% 下拉」定位，把窄條升級為一張精緻卡片——半透明暖米白底 `rgba(249,248,246,.85)` + `backdrop-blur`、圓角約 `16px`、柔和陰影 `0 8px 30px rgba(163,139,113,.15)`（棕金調陰影）、內距加大營造留白，連結間以極淡分隔線或純留白區隔。手機版加寬（如 `min(72vw, 300px)`）並拉高點擊區。
- **視覺（輕柔調性）：** ★★★★★ 毛玻璃＋暖米白＋棕金陰影與全站最契合，呼應 navbar 既有 `backdrop-blur-sm`，最能表達「輕柔留白」。
- **實作複雜度／改動範圍：** 低。僅改 `.mobile-dropdown` 的 CSS（背景、圓角、陰影、內距、寬度），HTML 結構與 JS 開合邏輯幾乎不動。桌機下拉的定位與 `translateY` 動畫沿用。
- **RWD 相容性：** ★★★★★ 與現有「桌機下拉／手機下拉」同一套定位模型相容，不改變資訊架構，衝突風險最低。
- **素材需求：** 無，純 CSS/Tailwind。

### 方案 B：右側滑入的側邊抽屜面板（drawer）
- **描述：** 手機版改為從畫面右緣滑入的全高（或大半高）抽屜，寬約 `78vw`、可搭配半透明遮罩層（overlay）覆蓋其餘畫面，連結大字距垂直排列，底部可放門市時間／社群小資訊。
- **視覺（輕柔調性）：** ★★★★ 沉浸感佳、留白充足，但抽屜＋遮罩偏「App 選單」語彙，氣質較現代俐落，需謹慎調色才不失輕柔。
- **實作複雜度／改動範圍：** 中高。需**新增遮罩層 DOM**、調整 z-index 層級、可能需鎖定背景捲動（`overflow:hidden`）、桌機與手機需明確分流（桌機仍維持下拉、手機才抽屜），JS 需為兩種模式做條件判斷，觸及既有開合狀態管理較多。
- **RWD 相容性：** ★★★ 改動資訊架構（手機變抽屜、桌機維持下拉），兩套行為差異加大，與「同一組 HTML/JS」現況衝突面較廣，回歸測試成本較高。
- **素材需求：** 無新圖，但需新增遮罩層元素與相應樣式。

### 方案 C：原位卡片化（最小改動）
- **描述：** 定位與動畫完全不動，僅將背景改暖米白、加大圓角與內距、換上柔和陰影、統一 hover 色，讓窄下拉變成一張「小卡片」。
- **視覺（輕柔調性）：** ★★★ 明顯優於現況，但因寬度與留白提升有限，精緻感不及 A。
- **實作複雜度／改動範圍：** 極低。純色票／圓角／陰影微調。
- **RWD 相容性：** ★★★★★ 零風險。
- **素材需求：** 無。

| 實作複雜度（越低越好） | 低 | 中高 | 極低 |

## 建議方案與理由

**採用方案 A（上方滑入的卡片式下拉面板 ＋ 毛玻璃 ＋ 圓角 ＋ 輕柔陰影）。**

理由：
1. **風格最契合且非憑空設計**——毛玻璃在 navbar 已有先例（`backdrop-blur-sm`），暖米白底、棕金陰影、`16px` 圓角、`.3s ease` 動畫皆直接沿用全站既有語彙，能一次拉齊「輕柔留白」調性，並順手修正目前粉橘硬編碼 `#FFDAC8` 與紅色 hover 這兩處與品牌調性的落差。
2. **改動範圍最小、風險最低**——保留現有下拉定位模型與整組 JS 開合／aria／點外部關閉／延遲關閉邏輯，幾乎只動 CSS，最不易破壞先前多輪調校的狀態管理。
3. **RWD 相容**——桌機下拉與手機下拉共用同一定位思路，不改資訊架構，回歸測試面小。

**關於方案 B 的實質差異提醒（供使用者知悉）：** 側邊抽屜會改變手機端的資訊架構與互動語彙（抽屜＋遮罩、背景鎖捲動），是「體驗方向」層級的差異而非純樣式微調，且與現況「同一組 HTML/JS 處理桌機＋手機」的架構衝突較大。若使用者日後希望往「更沉浸、可容納更多選單內容（如加入門市／社群區塊）」發展，再單獨評估 B 較合適。本次以 A 為優先。

## 技術風險與對策

| 風險項目 | 影響程度 | 對策 |
|---------|---------|------|
| 改 CSS 時破壞桌機下拉的 `translateY`/`visibility` 分流邏輯 | 中 | 修改前完整 Read 273–345 行；桌機 media query 區塊的定位/動畫維持不動，只改視覺屬性（背景/圓角/陰影） |
| 破壞先前多輪調校的 JS 開合狀態管理與 aria | 高 | 本次原則上「不改 JS」，僅動 CSS 與（可選）連結 class；如需改 JS 須逐項比對 845–882 行行為 |
| `backdrop-filter` 在部分瀏覽器/低階手機不支援或造成卡頓 | 中 | 提供 fallback：不支援時退回不透明暖米白底（`@supports` 或先設實色底再疊 blur）；實機測試開合流暢度 |
| 手機面板加寬後超出視窗或遮擋 Logo | 低 | 寬度用 `min(72vw, 300px)`，`right:0` 對齊；於窄螢幕實測 |
| hover 色由紅改棕金屬主觀美感變更 | 低 | 已於計畫說明理由（貼近輕柔調性），如客戶偏好保留紅色可快速還原 |

## 成功指標

- 面板配色、圓角、陰影、動畫 100% 取自全站既有語彙（毛玻璃、暖米白、棕金、`.3s ease`），無新增硬編碼粉橘色。
- 桌機版下拉選單開合行為與外觀定位「零回歸」。
- 手機版面板開合動畫在實機上流暢（無明顯掉幀／位移抖動），連結點擊區 ≥ 44px 觸控友善。
- 所有既有 aria 屬性（`aria-expanded`/`aria-controls`/`aria-label`）與點外部關閉／點連結關閉／延遲關閉行為完整保留。
- 不新增任何圖片素材。

## Generator 注意事項

1. **動工前務必完整 Read `index.html`**，特別是：CSS 第 273–345 行（`.mobile-dropdown` 全部規則含兩段 `@media (min-width:768px)`）、HTML 第 376–397 行、JS 第 839–882 行。此選單邏輯**先前經過多輪調校**，切勿憑印象改動。
2. **本次以「只改 CSS」為原則**，盡量不動 JS。既有的開合狀態管理（`.active` class 切換）、`aria-expanded`/`aria-label` 同步、`aria-controls`、點擊外部關閉、`mouseleave` 延遲 500ms 關閉、點錨點自動關閉，全部必須保留且行為不變。若確有需要調整 JS，須逐行比對第 845–882 行現有行為再改。
3. **桌機下拉的 media query 分流不可破壞**：`@media (min-width:768px)` 內的 `position/top/right/width/transform:translateY/visibility` 屬於桌機下拉專屬定位，本次只改「視覺屬性」（background、border、border-radius、box-shadow、padding），不改定位與動畫方向。
4. **色彩一律使用專案既有語彙**，禁止再引入新硬編碼色；暖米白 `#F9F8F6`/`brand-bg`、棕金 `#A38B71`/`brand-gold`、鼠尾草綠 `brand-accent`、既有漸層 `linear-gradient(135deg,#FFF9F2 0%,#FFB380 100%)`。移除現行 `#FFDAC8` 與 `#E5E5E5`。
5. **`backdrop-filter` 要加 `-webkit-` 前綴並提供 fallback 實色底**，避免不支援環境下面板變透明看不清文字。
